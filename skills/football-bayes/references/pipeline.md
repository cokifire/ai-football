# 流水线详解（S1–S7）

---

## S0 先确认比赛本身（10 秒内做完）

在分析任何东西之前，先确认：
- **对阵双方是谁**（队名歧义很常见：Sabah 是阿塞拜疆球队不是马来西亚的；Como 1907 是意甲的）
- **开赛时间的绝对时刻**（UTC + 北京时间 + 当地），并算出距开赛还有多久
- **赛事与轮次**（联赛第几轮 / 杯赛什么阶段）——这决定了战意与轮换概率
- **场地**（有些队欧战换球场，如萨巴赫在巴库奥林匹克而非自己的主场）

> **若距开赛 <1 小时**：只采集 Elo / xG / 赔率 / 伤停四项，其余标 UNAVAILABLE，并在报告顶部写时效警告。

> **宿主场景**：S0 跳过——对阵/时间/赛事/场地由宿主 prompt 给出，无需自查；仅做队名歧义快速核验（如 Sabah/Como），歧义在 `deep_report` 点出。

## S1 数据底板

采集 6 类。每类都要记来源。

### 1. Elo（长样本锚）
euroranking.net/en/{队A}-vs-{队B} 一次拿到双方 Elo、排名、近期战绩、每场 Elo 变动，以及**该站自己的预测概率**（很好的外部对照）。
- 记下近 30 日 Elo 变动（上升/下降趋势）
- 记下最近一场的 Elo 变动（最大冲击事件）

### 2. xG（短样本锚）
Understat 的**联赛表**（一次拿全部 20 队）+ **球队页**（拿逐场明细与主客场拆分）。

从联赛表算：
```
LG        = ΣxG / Σ队场                  （每队每场 xG，本联赛基线）
转化率    = Σ进球 / ΣxG
每场总进球 = 2 × Σ进球 / Σ队场
```
**自检**：ΣxG 应约等于 ΣxGA（两边都算一遍）。差 >2% 说明抓错了列或表不完整 → 在 §10 记录。

从球队页算：
```
xG/场、xGA/场、进球/xG（该队转化率）
主/客拆分 xG、xGA
```
**⚠ Understat 球队页的比分与 xG 是「主队在前」**，不是「本队在前」。判据：找一场你已知客场的比赛验证（若按"本队在前"读出来与已知结果矛盾，就是主队在前）。

### 3. 场地控制
控球率 + **Field Tilt（危险进攻占比）** + PPDA。FT 是最有用的（控球率会骗人）。

### 4. 环境
天气（多源，常冲突）、裁判（含执法风格数据）。

### 5. 人员
伤停（**至少两个源交叉**，冲突很常见）、预计首发、停赛。

### 6. 交锋与状态
H2H（含**交锋场均总进球**——这个数常常比胜率更有信息量）、近期连胜/连败/连续进球/连续丢球/零封纪录、教练对垒史。

> **宿主场景**：S1 退化为"读取宿主注入的数据段"——Elo/xG/赔率/积分/战绩/阵容/天气/情报 全由宿主给，**禁止采集** Understat/euroranking/赔率站等外部源。宿主没给的子项标 `UNAVAILABLE`，不补采。

## S2 P0 先验

### 锚一：Elo
```
有效差 = Elo_主 + HFA − Elo_客
两路份额 = two_way(有效差) = 1 / (10^(−有效差/400) + 1)
```
**必须扫 HFA ∈ {70, 85, 100}** 并列表。基准 85。

### 锚二：xG 比率桥接
```
λ_主 = xG_主 × xGA_客 / LG × f_主
λ_客 = xG_客 × xGA_主 / LG × f_客
f = 0.7 × 联赛转化率 + 0.3 × (本队进球 / 本队 xG)
```
主客场拆分用 `α = 0.25` 收缩：
```
x_adj = x_season × (x_split / x_season)^α
```
**α = 0 意味着不拆分。** 当拆分样本 <4 场或拆分归属不确定时，直接用 α = 0 并说明。

### 桥接 w 的经验标定（**每场都要做**）
```
predicted_goals = Σ_matches (xG_i × 对手赛季xGA/场)^w / LG^(2w−1)
```
对比实际进球，扫 w ∈ {0.5, 0.75, 1.0}。
- **结果会随联赛和球队强度变化**（详见 pitfalls §1）。
- 基准仍用 w = 1.0（跨场次可比），但**必须在报告里给出扫描结果 + 全区间敏感性**。

### 混合
`P0 = we × Elo锚 + (1−we) × xG锚`，基准 `we = 0.6`。**必须扫 we ∈ {0, 0.4, 0.6, 0.8, 1}**。

### 两锚分歧（本框架最重要的诊断量）
| 分歧 | 含义 | 处理 |
|---|---|---|
| <5pp | 两锚共识强，结论可信 | 正常输出 |
| 5–12pp | 有真实张力 | 60/40 混合 + 全区间敏感性 + 列为风险 |
| >12pp | **输入层面有问题** | 除上述外，还要检查是否有一方的评级被"弱联赛统治表现"污染（pitfalls §6） |

> **宿主场景**：S2 跳过——P0 已由宿主给出，双锚合成（HFA 扫描 / w 扫描 / we 混合）整步不做，不重算 P0。两锚分歧诊断仍可做（对比宿主 Elo 锚与 XGBoost 锚的结论方向），仅用于 `deep_report` 解释，不回写 P0。

## S3 战术语境修正（似然）

列 **10–14 条因子**，每条给出：
- 方向（pp，三路之和必须为 0）
- 可追溯的证据（一句话 + 来源）

典型因子：主场/客场战绩、进攻上限（是否"一球队"）、连续进球/丢球纪录、交锋压制、伤停面（分主客）、赛程密度/旅途、超预期射手的回归压力、战意、教练对垒。

**NET = 三路净修正**，标为 ASSUMPTION 集。

> **不要重复计量**：Elo 已经反映了近期战绩（每场都在变），所以"近期状态差"这类因子要小心不要和 Elo 的下降重复计入。处理办法：看该队近 30 日 Elo 变动量，若已跌了很多，状态因子的幅度就要打折。

> **宿主场景**：宿主贝叶斯层的"证据账本"已把可修正项 `applied` 过一次（P0→P1）。S3 只对**账本未覆盖**的战术语境（如宿主没列的阵容缺口、战意、赛程疲劳）做修正，并标注 `ASSUMPTION`；账本已 applied 的项不再修第二次。NET 修正只用于 `deep_report` 解释与剧本，**不回写 P1**（P1 用宿主的）。

## S4 P1 后验

```
P1 = P0 + NET/100
模型自洽输出 = solve_lambda(P1_主/(P1_主+P1_客), T)["model"]
```
**后续所有派生市场都用"模型自洽输出"**，保证 λ 与三路概率内部一致。

**⚠ 必查**：手工 P1 与自洽输出的**平局**若差 >1.5pp，说明 T 太低、平局被泊松结构封顶。此时必须在报告中说明："本次似然更新中抬高平局的部分被固定的 T 吃掉了"，并给出"若要达到该平局概率，T 需要是多少"。

> **宿主场景**：S4 跳过——P1 已由宿主给出，不重解 λ、不做"模型自洽输出"。后续 S5 派生市场直接用宿主的 P1 + 宿主的 λ 算泊松矩阵。若想核验宿主 P1 与 λ 的一致性，仅在 `deep_report` 提一句，不重算。

## S5 派生市场

至少输出：
- O/U 1.5 / 2.5 / 3.5 / 4.5 与 BTTS
- 0-0 与 1-1
- 亚洲盘表（**客队让为正**，与 `handicap_num` 同向）+ **至少 2 项交叉校验**
- 1X / X2 / 12 / 双方 DNB
- 比分 TOP10
- 双方进球 ≥1 / 零封
- 球队进球 O0.5 / O1.5 / O2.5
- 全部公平赔率

**亚盘校验模板**（写进报告）：
```
口径：handicap_num（正=客队让，负=主队让）；半线无走水，两侧互补=100%
-0.5(主让0.5)  主覆盖=主胜          客覆盖=客胜+平
+0.5(客让0.5)  主覆盖=主胜+平       客覆盖=客胜
-1.0(主让1)    主覆盖=主胜≥2+主胜1×半注   客覆盖=客胜+平+主胜1×半注
+1.0(客让1)    主覆盖=主胜+平+客胜1×半注  客覆盖=客胜≥2+客胜1×半注
 0             DNB（平=走水）
```

## S6 稳健性网格

| 模式 | 扫什么 | 组数 |
|---|---|---|
| 同联赛 | HFA(3) × w(3) × Elo权重(3) × α(3) × 似然(2) | **162** |
| 跨联赛 | HFA(3) × LG_ref(5) × Elo权重(3) × 似然(2) | **90** |
| 单锚（xG 缺失） | HFA(3) × T(6) × 似然(2) | **36** |

输出每个量的 **[min, max] 与中位数**，并回答：
1. 市场值是否落在模型区间**内部**？（落在内部 = 无分歧；完全在外 = 强分歧）
2. 有多少组规格能达到/低于市场值？（如 "0/162" 或 "162/162"）
3. **方向是否因参数设定而反转？**

**必做 T 敏感性表**：T 从 −0.5 扫到 +0.6（相对基准），列出三路 + O2.5 + BTTS + 0-0。
> 这条几乎永远成立：**三路对 T 极不敏感，进球数盘对 T 极度敏感。** 所有"进球数"结论本质都是对 T 的赌注 —— 必须在报告里明说。

## S7 外部交叉验证

至少找 **4 个**独立来源：市场共识、一家 Elo 站、一家统计模型站、一家人工预测站。做一张对照表。

**异常值处理**：某来源与其余全部矛盾（如 APWin 给平局 8.00、Oddspedia 给主队 47%）→ 判定"不可采信"并在 §10 记录理由，不要纳入平均值。

**最有价值的对照是"历史基准"**（完全独立于任何评级模型的经验分布），例如：
- "阿塞拜疆球队对五大联赛球队 14 战 1胜3平10负"
- "某队近 10 次交锋场均总进球 1.2 个"

这类基准经常能直接裁定"模型 vs 市场"谁对。

> **宿主场景**：S7 退化为"宿主情报对比"——只用宿主【外部比赛情报】里的信息做异常值/历史基准对比，**禁止联网**找 4 个外部源（市场共识/Elo 站/统计模型站/人工预测站一律不访问）。宿主已给的 Elo 与 XGBoost 本身就是两个独立锚，可作交叉。情报缺失时按 `UNAVAILABLE` 处理，不补采。

## 降级路径（数据不全时怎么办）

| 缺失 | 处理 | 报告要求 |
|---|---|---|
| 一方 xG 不可得 | 单 Elo 锚 + `T_override` + 扫 T | §1 写明；可信度下调一档；§9 第 1 条列为最高风险 |
| 两队跨联赛 | `cross=True` + `LG_ref` 扫描 | §11 写明公式；§9 列为最高风险 |
| 控球/FT/PPDA 全无 | 陷阱检验写 UNAVAILABLE | §1.3 + §9 说明"本场检验无法执行" |
| 赔率只拿到 1–3 家 | 就列这几家，不要平均成"市场" | §6.1 注明样本小 |
| 时间 <30 分钟 | 只做 Elo + xG + 1X2 + 伤停 | 顶部时效警告；§10 列所有未采项 |

> **宿主场景**：降级表的"采集/时间"维度不适用——宿主已注入全部数据，无采集时效问题。宿主场景的降级只发生在"墙钟预算"维度（见 SKILL.md「宿主集成模式」§5）：网格缩减、S7 不联网。
